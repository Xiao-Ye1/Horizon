## [Debate Over Using JWTs for Browser Sessions](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 8.0/10

A GitHub gist titled 'Stop Using JWTs' sparked a Hacker News debate with over 200 points and 130 comments, critically examining the security of JSON Web Tokens for browser-based session management and discussing trade-offs with cookie-based sessions. This debate highlights critical security concerns that affect many web applications relying on JWTs for authentication, potentially guiding developers toward more secure session management practices. Key points include: JWTs stored in localStorage are vulnerable to XSS attacks, while httpOnly cookies mitigate exfiltration but introduce CSRF risks; JWT revocation can be managed with short expiry times and refresh tokens, comparing favorably to traditional session revocation in some scenarios.

hackernews · dzonga · Jun 16, 16:49 · [Discussion](https://news.ycombinator.com/item?id=48558147)

**Background**: JSON Web Tokens (JWT) are an open standard (RFC 7519) that defines a compact and self-contained way for securely transmitting information between parties as a JSON object. They are commonly used for authentication, where the server generates a token containing user claims signed with a secret or private key. In browser applications, JWTs can be stored in localStorage, sessionStorage, or cookies, each with different security implications. Cookies can be marked httpOnly to prevent JavaScript access, reducing XSS risk, but may require additional CSRF protection.
